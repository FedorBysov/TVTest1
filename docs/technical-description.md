# TVTest1 — техническое описание прототипа

## Класс и область применения

TVTest1 — статическое desktop веб-приложение для демонстрации учебных принципов БЩУ. Его класс по общим определениям МАГАТЭ ближе к **generic/basic-principles graphical simulator**, а не к plant-referenced full-scope simulator: нет референтной станции, согласованного перечня приборов, проектных чертежей, моделей основных систем и валидации для эксплуатации. См. `docs/references.md` и `COVERAGE.md`. VR исключён решением пользователя.

## Состав

| Слой | Назначение |
| --- | --- |
| React + TypeScript + Vite | Страницы, управление состоянием, сборка статического сайта |
| `src/sim/model.ts` | Чистый reducer условной модели, действия, один `DisplaySnapshot`, журнал |
| `src/sim/assessment.ts` | Чистая оценка демонстрационного порядка и пропусков по журналу |
| `src/scene/*` + Three.js | Панорамный 3D-пост, выбор зон, кликабельные органы, кинематика |
| `src/figure/*` + локальный Anatomy kit | Крупный изометрический SVG-модуль, физические детали и доступные действия |
| `cad/generate_parts.py` + build123d | Параметрический источник трёх деталей; STL в `public/assets/cad/` |
| `src/app/group/*` | Локальный обмен действиями и снимками между вкладками через `BroadcastChannel` |
| `src/app/storage.ts`, `migrateSession.ts` и `sessionValidation.ts` | Запись, миграция и проверка локального сохранения |

Профили ВВЭР и СМР меняют учебную кривую и визуальную компоновку. Пять этапов и отклонения используют одни типы событий. Числа нормированы к 0–100 и не описывают действительную термогидравлику. `ACK` не меняет причину; `RESOLVE` меняет её отдельно. `OBSERVE` записывает выбранную зону и снимок; оценщик использует события журнала, не скрытый счётчик.

## Поток данных

`действие → reduceSession → SessionState → deriveSnapshot → 3D / SVG / HTML / график`. В момент журналируемого действия сохраняется неизменяемый снимок. Исторические записи читаются без возврата модели к прошлому состоянию. Первый реальный ход времени каждого этапа записывается сразу; затем автоматические отсчёты сохраняются при пересечении 10-секундных границ. Полный журнал ограничен 500 событиями, а компактное свидетельство выполненных/нарушенных учебных шагов сохраняется отдельно, чтобы оценка не исчезала при вытеснении ранних записей. При переключении профиля или сбросе начинается новая сессия.

Индивидуальная сессия хранится в `sessionStorage` конкретной вкладки (`tvtest1.session.v3`); тема и выбранная зона — в `localStorage`. Старые форматы v1/v2 импортируются из `localStorage` с обновлением полей снимков. Такой раздельный ключ не даёт вкладкам перезаписать индивидуальные занятия друг друга. Закрытие вкладки завершает индивидуальную сессию; JSON-экспорт предназначен для сохранения её результатов пользователем.

Обмен вкладок в группе направляет действия участников ведущей вкладке. Только ведущий применяет reducer и рассылает версионированные снимки. Участники не исполняют собственный таймер модели. Проверка роли ограничивает управление щитом; наблюдатель может записать наблюдение. Потеря ведущего прекращает приём команд, чтобы вкладки не разошлись. `BroadcastChannel` работает только между вкладками одного origin; это не сервер и не сеть между устройствами. Код группы выбирает канал, но не является криптографической аутентификацией.

## Данные, сеть и ограничения

Приложение не содержит протоколов промышленной автоматизации, подключения к контроллерам или реальной телеметрии. Для обучения используются только локальные учебные данные. Сценарии, размеры и органами управления нельзя пользоваться как рабочей документацией АЭС. Изображения из референсов не включены в сайт.

Приложение публикуется как статические файлы GitHub Pages из `dist/`; URL base — `/TVTest1/`, страницы используют hash-маршруты. В рабочей версии нет пользовательского аккаунта, централизованного архива занятий или сервера для удалённой группы. Файл JSON, экспортируемый из разбора, остаётся у пользователя. Для учебной организации, которой нужны учётные записи, протоколы доступа, синхронизация разных компьютеров и долговременное хранение, понадобится отдельный проект серверной части и согласование требований к персональным данным.

## Запуск и повторная сборка

Требования: Node.js 22.12+ и npm для сайта; Python 3.13 и `build123d==0.13.0` только для повторного выпуска CAD. Готовые STL уже находятся в репозитории.

```sh
npm ci
npm run dev
npm test
npm run build
node scripts/verify-structure.mjs --dist
```

Локальный Vite открывается по `http://127.0.0.1:5173/TVTest1/`, если порт свободен. Production build находится в `dist/`. Для проверки собранной версии выполните `npm run preview`. Страница не предназначена для открытия через `file://`.

Параметрические детали генерируются из `cad/generate_parts.py` командой `.venv/bin/python cad/generate_parts.py`; `--check` строит копии и сверяет геометрию/manifest без изменения итоговых STL. Рабочий проект находится только в TVTest1 и не использует файлы `engine`.

## Проверки и критерии выпуска

Перед публикацией выполняются `npm test`, `npm run build`, `npm run verify:structure`, `node scripts/verify-structure.mjs --dist`, CAD `--check` и визуальный осмотр desktop-размеров 1280×800, 1440×900, 1920×1080 для обоих профилей и тем. Браузерный маршрут охватывает пять этапов, оба отклонения, сигнал и его квитирование, исторический снимок, экспорт отчёта и подключение отдельной вкладки группы. Результаты фиксируются в `TASKS.md` и `COVERAGE.md` по факту проверки.

Эти проверки подтверждают работоспособность веб-прототипа. Они не являются валидацией инженерной модели, квалификацией оперативного персонала, приёмкой аппаратного комплекса либо исполнением договорных условий.
