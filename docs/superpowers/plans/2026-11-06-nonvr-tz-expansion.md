# TVTest1: план расширения не-VR требований

**Цель:** закрыть доступные веб-прототипу пробелы исходного ТЗ и честно классифицировать остальные. Проектное решение: `../specs/2026-11-06-nonvr-tz-expansion.md`.

**Рабочая ветка:** `feat/tz-nonvr-coverage`. Файлы создаются только в TVTest1. После проверок слить в `main`, запушить, дождаться Pages и проверить сайт.

## Пакет A — модель, занятия и оценка

- [ ] A1. Зафиксировать тестами требования к наблюдению, системам, порядку действий и итогам.
- [ ] A2. Расширить модель событиями учебного наблюдения и конкретными состояниями связанных систем.
- [ ] A3. Добавить чистый оценщик пяти этапов и двух отклонений с объяснением ошибок и пропусков.
- [ ] A4. Обновить валидацию сохранённой сессии и тесты регрессии.

## Пакет B — визуальная модель щита

- [ ] B1. Построить расширенную многосекционную компоновку с разными силовыми, системными и сигнальными блоками.
- [ ] B2. Согласовать 3D-приборы, табло, лампы и органы управления с одним снимком.
- [ ] B3. Различить ВВЭР и СМР силуэтом, добавить физические опоры и читаемую маркировку.
- [ ] B4. Проверить picking, CAD, кинематику, геометрию и WebGL fallback.

## Пакет C — страницы и взаимодействие

- [ ] C1. Показывать текущий этап в общей шапке и именованные состояния систем на пульте.
- [ ] C2. На странице сценариев показывать задания и следующий учебный шаг; регистрировать наблюдения.
- [ ] C3. На странице разбора показывать выполненные/пропущенные/ошибочные действия и основания.
- [ ] C4. Согласовать фигуру Anatomy с выбранной зоной и состоянием сигнализации.

## Пакет D — группа

- [ ] D1. Определить модель ролей, ведущего занятия и синхронизации нескольких вкладок.
- [ ] D2. Реализовать обмен действиями и версионированными снимками между вкладками.
- [ ] D3. Проверить права ролей и авторство, потерю ведущего, разрыв/повторное подключение.
- [ ] D4. Отразить границу одного браузера и отсутствие сетевого сервера на опубликованном сайте.

## Пакет E — документация и приёмка

- [ ] E1. Составить реестр открытых первичных референсов и правил их использования.
- [ ] E2. Написать руководство, техническое описание и сценарий демонстрации.
- [ ] E3. Исправить `COVERAGE.md` и `TASKS.md` по фактическому результату; отдельно перечислить договорные и физические пункты.
- [ ] E4. Пройти desktop-маршруты, две темы, оба профиля, сохранить контрольные кадры.
- [ ] E5. Выполнить `npm test`, `npm run build`, `npm run verify:structure`, CAD `--check` и браузерную проверку.
- [ ] E6. Опубликовать проверенную ветку в `main`, дождаться успешного GitHub Pages, проверить удалённый коммит и живой сайт.

Результат каждого пакета принимается только по наблюдаемому поведению и проверкам, а не по количеству созданных файлов.
